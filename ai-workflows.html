AI Workflows

Two coding assistants work from the same rules: J.A.R.V.I.S. runs on Claude Code and E.V. runs on Codex. The kit is open source under the MIT licence: github.com/SKULLSHOCK3R/ai-workflows.

What it does

A single rulebook (AGENTS.md, with a byte-identical CLAUDE.md) governs both assistants, so the same rules apply whichever one picks up a task. Any non-trivial task is split into fresh-context stages, and the last stage is always a separate, independent review.

How it is built, and the engineering practices

  • Checked at session start. A session-start hook verifies the core files and that the two rulebook copies match by SHA-256, then prints a short manifest that stays under Claude Code's 10,000-character hook limit. A per-message hook re-injects a short persona card.
  • Staged work. Planning, production and independent final review run as separate fresh-context stages. There are six stage roles across three model tiers. A strict quick-task test may skip planning, but never the review.
  • Approval guardrails. Each paid call needs its own yes, with a cost estimate and a ceiling. Outgoing messages need approval of the exact text and recipients. Instructions found inside emails or web pages are treated as data, not commands.
  • Safe change handling. Commit before editing, no history rewriting, hashed backups, and a recovery protocol for a stage that is cut off part way.
  • File intake. New files are checked for stability with SHA-256 and archived only after an approval.
  • Memory. Dated, scoped lessons record corrections so the same mistake is not repeated.
