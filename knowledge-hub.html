Personal Knowledge Hub

A local notes app that turns Markdown notes and the links between them into a 3D star map you can chat with.

What stays on my PC

  • The app's server listens only on my PC, not on the network.
  • Answers are drawn from my notes, for free, wherever possible.
  • Questions that need reasoning go to Claude over the internet, and only after I confirm the cost.
  • The phone assistant is a Telegram bot, so those messages pass through Telegram.

What it does

  • Answers locally and for free first. Claude is used only after I confirm.
  • A model switch lets me change the AI model from a fixed list of supported names.
  • Browser voice, a "remember that" capture, and screen-share questions.
  • A link to my home-automation system that uses a separate, limited (non-admin) token and an allowlist of 15 readings and 5 actions. Anything else is refused. Each action needs a confirmation that works once and expires after 60 seconds.

How I built it

  • Sending fewer notes. Before a paid question goes to Claude, a free scan of the notes picks the ones worth sending: at most 3 (4 when the scan finds nothing), instead of 6. I measured this offline on 4 October 2026, when the feature shipped, over 33 test questions, with Opus 5.5 priced at US$4 per million input tokens and US$20 per million output tokens. The average text sent fell from 12,858 to 5,720 characters (about 56% fewer), and the estimated cost fell from 2.29 to 1.47 US cents (about 36% lower). The expected note was still included in 25 of the 25 cases where one was expected; that checks which notes were sent, not whether the answers were accurate. The costs are estimates, not billed amounts.
  • Paid-call gate. Every paid call needs a single-use offer that I answer, and each offer states an "at most" cost ceiling. The software library's automatic retries are switched off, because its default of two retries could bill one confirmed yes three times.
  • Exact model names. The model-name parser is strict: it builds the exact name from the family and version and refuses anything not on the supported list. Fuzz testing (feeding it many near-miss inputs) caught a near match that loaded the wrong model, and it is now refused.
  • Testing (13 October 2026). A 51-suite offline test battery had 32 suites exit cleanly and 19 older suites report failures; those 19 reported the same failures as the previous run, so no new failures appeared. A live preflight (a health check of the running app), run free so it made no paid calls, ran 42 checks: 36 passed, 0 failed and 6 gave warnings (2 paid checks that the free run skips, and 4 about optional features that are not set up). The test suite for the home-automation link ran 381 checks with 0 failures. Changes to tested files are recorded as reversible patches.
