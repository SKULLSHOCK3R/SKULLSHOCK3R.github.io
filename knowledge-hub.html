Personal Knowledge Hub

A local notes app that turns Markdown notes and the links between them into a 3D star map you can chat with.

What stays on my PC

  • The app's server listens only on my PC, not on the network.
  • Answers are drawn from my notes, for free, wherever possible.
  • Questions that need reasoning go to Claude over the internet, and only after I confirm the cost.
  • The phone assistant runs through a messaging app, so those messages pass through that service.

What it does

  • Answers locally and for free first. Claude is used only after I confirm.
  • A model switch lets me change the AI model from a fixed list of supported names.
  • Browser voice, a "remember that" capture, and screen-share questions.
  • A map of my own PC. A local index of file names across my chosen folders, shown as stars on the map. File-content search covers common document types; it keeps only a short excerpt of each file, skips very large files, cloud-only files and files with secret-looking names, and shows only short snippets that are never logged. "Find my file" falls back to text when no name matches, and "open my file" never opens a file that was found only by its text.
  • Automatic rescan. The index refreshes by itself on a schedule, and a manual rescan is available. The index stays on my PC and is never served to the network.
  • Explorer highlight. Opening a result selects the file in Windows File Explorer, even when that folder is already open.
  • Scripts cannot spend. A request from a local script (rather than the hub's own page on my PC or my paired phone) cannot confirm a paid offer or answer an inbox question. A script may decline an offer or let it lapse, but it may not spend.
  • Wake word (phase 1: built and tested offline, not yet switched on). Once it is on, saying the wake word will show the hub's widget, with a chime. Nothing listens for a command afterwards. In this mode the listener opens no network connection, and its logs hold no audio, transcripts or replies.
  • A link to my home-automation system that uses a separate, limited (non-admin) token and a short allowlist of readings and actions. Anything else is refused. Each action needs a confirmation that works once and expires quickly.

Research bay: Pythagoras

Pythagoras is a research bay inside the hub. It looks at public web pages in an observe-only way, using an open-source page-inspection tool in a throwaway headless browser (a browser with no visible window that is deleted afterwards).

  • Observe only. It never clicks, types, signs in or sends cookies or credentials.
  • Public pages only. It refuses local and private addresses, raw IP addresses, file paths and local development servers. An independent review on 15 October 2026 probed 28 kinds of refusal.
  • One command at a time. Only a short allowlist of commands is accepted, and the final address is checked again after any redirect.
  • Pinned tool. The inspection tool is version-pinned, the hub checks the installed version and integrity hash against the pins, and the tool was installed by hand (a pinned manual install, not by the app) after its registry signatures were checked.

It belongs to the ethics layer described on the AI Workflows page.

How I built it

  • Sending fewer notes. Before a paid question goes to Claude, a free scan of the notes picks the ones worth sending: at most 3 (4 when the scan finds nothing), instead of 6. I measured this offline on 4 October 2026, when the feature shipped, over 33 test questions, with Opus 5.5 priced at US$4 per million input tokens and US$20 per million output tokens. The average text sent fell from 12,858 to 5,720 characters (about 56% fewer), and the estimated cost fell from 2.29 to 1.47 US cents (about 36% lower). The expected note was still included in 25 of the 25 cases where one was expected; that checks which notes were sent, not whether the answers were accurate. The costs are estimates, not billed amounts.
  • Paid-call gate. Every paid call needs a single-use offer that I answer, and each offer states an "at most" cost ceiling. The software library's automatic retries are switched off, because its default of two retries could bill one confirmed yes three times.
  • Exact model names. The model-name parser is strict: it builds the exact name from the family and version and refuses anything not on the supported list. Fuzz testing (feeding it many near-miss inputs) caught a near match that loaded the wrong model, and it is now refused.
  • Testing (13 October 2026). A 51-suite offline test battery had 32 suites exit cleanly and 19 older suites report failures; those 19 reported the same failures as the previous run, so no new failures appeared. A live preflight (a health check of the running app), run free so it made no paid calls, ran 42 checks: 36 passed, 0 failed and 6 gave warnings (2 paid checks that the free run skips, and 4 about optional features that are not set up). The test suite for the home-automation link ran 381 checks with 0 failures. Changes to tested files are recorded as reversible patches.
